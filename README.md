# SysProg2026

Учебный репозиторий по системному программированию.

Репозиторий содержит материалы и эксперименты с лекций: от минимального ELF-файла, собранного вручную в hex-редакторе, до первых шагов к собственной учебной операционной системе.

> Проект находится в активной разработке. Материалы в первую очередь рассчитаны на тех, кто посещал лекции и знаком с контекстом упражнений.

## Структура репозитория

```text
.
├── minimal/   # минимальный Hello World и разбор ELF/машинного кода
├── hello/     # эксперимент с адресами, строками и виртуальной памятью
└── molokos/   # заготовка учебной ОС MolokOS
```

## minimal

Папка `minimal` содержит результат упражнения по ручному созданию простого `Hello World`.

Что внутри:

- `minimal.txt` — заметки с разбором C-программы, системных вызовов, машинных инструкций и структуры ELF;
- `minimal.bin` — бинарный результат.

Идея упражнения — показать, что исполняемый файл не является «магией»: его можно разобрать до байтов, ELF-заголовков, сегментов, машинных инструкций и строки `Hello World!`.

## hello

Папка `hello` содержит небольшой Windows/C++-эксперимент с виртуальной памятью.

Программа:

- хранит строку в пользовательском адресном пространстве;
- печатает саму строку и её адрес;
- делает это в бесконечном цикле с задержкой.

Этот пример используется как учебная точка входа для обсуждения адресов, виртуальной памяти, процесса и того, что именно видит пользовательская программа.

## molokos

`molokos` — начало учебной операционной системы.

Сейчас здесь есть две основные части:

```text
molokos/
├── kernel/   # низкоуровневый boot/kernel-код, сборка образа и запуск в QEMU
└── loader/   # экспериментальный UEFI-загрузчик ELF-ядра
```

### molokos/kernel

В `molokos/kernel` находятся:

- `boot.asm` — MBR/boot-код для загрузки kernel image;
- `boot64.asm` — код перехода в 64-битный режим;
- `boot_mb.S` — дополнительный boot-код;
- `kernel.c` — C-код ядра;
- `linker.ld` — linker script;
- `makefile` — сборка и запуск образа.

Текущий `kernel.c` работает с VGA text buffer и выводит сообщение на экран. Это ещё не полноценная ОС, а минимальная среда для экспериментов с загрузкой, режимами процессора, линковкой и запуском C-кода без стандартной библиотеки.

### molokos/loader

В `molokos/loader` находится экспериментальный UEFI-загрузчик:

- читает `\kernel\kernel.elf`;
- проверяет ELF64-заголовок;
- загружает `PT_LOAD`-сегменты;
- передаёт управление entry point ядра.

Эта часть полезна для дальнейших экспериментов с UEFI, ELF-загрузкой и переходом от загрузчика к ядру.

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone https://github.com/sit-itmo/SysProg2026.git
cd SysProg2026
```

### 2. Посмотреть минимальный ELF-пример

```bash
cd minimal
ls
```

`minimal.txt` лучше читать рядом с `minimal.bin`: так проще сопоставлять байты, инструкции и структуру исполняемого файла.

### 3. Собрать и запустить MolokOS

Для сборки kernel-части нужны инструменты вроде:

- `make`;
- `gcc`;
- `ld`;
- `objcopy`;
- `nasm`;
- `qemu-system-x86_64`.

Сборка и запуск:

```bash
cd molokos/kernel
make
make run
```

Отладочный запуск QEMU:

```bash
make rundbg
```

Очистка:

```bash
make clean
```

## Текущий статус

- `minimal` — завершённый учебный пример ручного Hello World/ELF.
- `hello` — упражнение по виртуальной памяти и адресам в пользовательском процессе.
- `molokos` — ранняя стадия учебной ОС: есть boot-код, linker script, kernel на C и запуск через QEMU.

## Известные проблемы и ближайшие задачи

В `molokos` сейчас есть несколько мест, которые стоит проверить и обсудить на лекции:

1. **Стек перед входом в C-код.**  
   При переходе в 64-битный режим нужно убедиться, что перед вызовом C-кода корректно настроен `rsp`.

2. **Согласованность 32/64-bit сборки.**  
   В makefile одновременно видны признаки 64-битной и 32-битной сборки. Нужно явно договориться, какой режим сейчас является целевым для kernel image.

3. **Переход от boot-кода к kernel.c.**  
   Нужно проверить, что формат ELF, linker script, адреса загрузки и entry point согласованы между собой.

4. **Дальнейший вывод из ядра.**  
   Сейчас базовый вывод в VGA text buffer уже есть, но полноценный `printf`/форматированный вывод требует аккуратной реализации без стандартной библиотеки.

## Для кого этот репозиторий

Репозиторий будет особенно полезен студентам, которые посещают лекции по системному программированию и хотят:

- повторить материалы после занятия;
- руками потрогать ELF, машинный код и загрузку;
- разобраться с виртуальной памятью;
- поучаствовать в разработке учебной ОС;
- найти и исправить ошибки в `molokos`.
